审批结论：当前计划不建议直接进入实现。方向是对的，但语音/TTS 这块和 AIAgent 现有 VOICE 路径、Launcher ASR 依赖、权限/生命周期之间有几处会直接导致重复播报、编译失败或运行状态错乱的问题。
P0 必须修正
TTS 归属冲突没有解决，按计划会重复播报。 文档先写 AIAgent 端 handleVoiceRequest() 已经播报，又说 TestApp 侧统一播报并告知 AIAgent 不要重复播报：[voice-input-tts-design.md (line 131)](D:/code/android/AndroidStudioProjects/AIAgentTestApp/docs/superpowers/specs/2026-07-06-voice-input-tts-design.md:131)。但当前 AIAgent VOICE 路径固定调用 mManager?.speak(res)：[AIAgentService.kt (line 593)](D:/code/android/AndroidStudioProjects/AIAgent/app/src/main/java/com/hirain/aiagent/AIAgentService.kt:593)，TestApp 无法单方面关闭它。要么本阶段使用 inputType=TEXT 发送 ASR 结果并由 TestApp 播报；要么使用 inputType=VOICE 测 AIAgent 端语音路径，但 TestApp 不再本地 TTS。
文档说 AgentRequest 无 extraContext 字段是事实错误。 TestApp 的 AgentRequest 已有 extraContext Parcelable 支持：[AgentRequest.java (line 18)](D:/code/android/AndroidStudioProjects/AIAgentTestApp/app/src/main/java/com/hirain/aiagent/AgentRequest.java:18)。但 AIAgent 当前 VOICE 路径没有读取 request.extraContext，只手工构造 user_id + traceContext：[AIAgentService.kt (line 580)](D:/code/android/AndroidStudioProjects/AIAgent/app/src/main/java/com/hirain/aiagent/AIAgentService.kt:580)。所以“通过 extraContext 告知 AIAgent 不播报”不是 TestApp 单侧可完成的方案。
ASR 初始化位置不成立。 文档要求 MyApplication.onCreate() 初始化：[voice-input-tts-design.md (line 26)](D:/code/android/AndroidStudioProjects/AIAgentTestApp/docs/superpowers/specs/2026-07-06-voice-input-tts-design.md:26)，但 Launcher 的 ASRManager 构造函数需要 Activity，权限申请也通过 XXPermissions.with(activity)：[ASRManager.java (line 143)](D:/code/android/AndroidStudioProjects/Launcher/app/src/main/java/com/hirain/launcher/asr/ASRManager.java:143)。SDK 核心初始化可以拆到 Application，但权限申请、录音启动必须在 Activity 生命周期里管理。
P1 高风险
权限清单不完整。 计划只提 RECORD_AUDIO：[voice-input-tts-design.md (line 24)](D:/code/android/AndroidStudioProjects/AIAgentTestApp/docs/superpowers/specs/2026-07-06-voice-input-tts-design.md:24)，但 Launcher 还声明 INTERNET、MODIFY_AUDIO_SETTINGS，并为 TTS 服务加了 <queries>：[AndroidManifest.xml (line 19)](D:/code/android/AndroidStudioProjects/Launcher/app/src/main/AndroidManifest.xml:19)。当前 TestApp manifest 只有 AIAgent 包可见性，没有录音和网络权限：[AndroidManifest.xml (line 1)](D:/code/android/AndroidStudioProjects/AIAgentTestApp/app/src/main/AndroidManifest.xml:1)。
依赖清单少了 Codec.aar，且没说明 Version Catalog。 Launcher 同时依赖 SparkChain.aar 和 Codec.aar：[build.gradle (line 83)](D:/code/android/AndroidStudioProjects/Launcher/app/build.gradle:83)。计划只列 SparkChain.aar：[voice-input-tts-design.md (line 161)](D:/code/android/AndroidStudioProjects/AIAgentTestApp/docs/superpowers/specs/2026-07-06-voice-input-tts-design.md:161)。TestApp 当前用 libs.versions.toml 管理依赖：[libs.versions.toml (line 1)](D:/code/android/AndroidStudioProjects/AIAgentTestApp/gradle/libs.versions.toml:1)，计划需要明确新增 xxpermissions catalog 项，以及本地 AAR 文件位置。
直接复制 ASRManager 会编译失败或引入无关依赖。 Launcher ASRManager 使用 lombok.Setter：[ASRManager.java (line 23)](D:/code/android/AndroidStudioProjects/Launcher/app/src/main/java/com/hirain/launcher/asr/ASRManager.java:23)，TestApp 没有 Lombok。计划应该写“移除 Lombok，显式提供 setter”，而不是复制。
上滑取消逻辑会被 ASR 最终回调击穿。 Launcher 的 stopAsr() 在音频模式下调用 mAsr.stop(false)，含义是等待最后一帧结果：[ASRManager.java (line 311)](D:/code/android/AndroidStudioProjects/Launcher/app/src/main/java/com/hirain/launcher/asr/ASRManager.java:311)。如果用户上滑取消后仍收到 status=2，当前回调会触发 onResult()：[ASRManager.java (line 49)](D:/code/android/AndroidStudioProjects/Launcher/app/src/main/java/com/hirain/launcher/asr/ASRManager.java:49)。计划需要增加 isCanceling/isIgnoringResult 状态，取消时丢弃最终识别结果。

生命周期没有闭环。 计划没有写 TextToSpeech.stop()/shutdown()、ASR stop、AudioRecorder release、Activity 销毁时回调解绑。Launcher 的 AudioRecorderManager 会释放 AudioRecord 和单例：[AudioRecorderManager.java (line 190)](D:/code/android/AndroidStudioProjects/Launcher/app/src/main/java/com/hirain/launcher/utils/AudioRecorderManager.java:190)，TestApp 需要显式纳入生命周期设计。
P2 设计需澄清

把 Launcher 的 appid/apikey/apiSecret 复制到 TestApp strings.xml 风险较高：[voice-input-tts-design.md (line 25)](D:/code/android/AndroidStudioProjects/AIAgentTestApp/docs/superpowers/specs/2026-07-06-voice-input-tts-design.md:25)。如果只是本地测试可以接受，但计划中应标注这是测试凭证、不要提交生产密钥。
我建议先决定一个核心方向：本阶段到底是“测试 AIAgent 的 VOICE 路径”，还是“给 TestApp 增加语音输入体验”。
如果是前者，ASR 结果发送 VOICE，TTS 默认交给 AIAgent，TestApp 只显示回复；如果是后者，ASR 结果发送 TEXT，TestApp 自己播报，避免 AIAgent 端重复 TTS。当前文档把两者混在一起，这是最大漏洞。
